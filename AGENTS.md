# Repository automation boundaries

- Work only inside this Smarter Justice repository and its declared package root.
- Never read, print, request, commit, or transmit production secret values.
- Deployment preparation is allowed; production deployment requires Roger's exact product-scoped command and a qualified exact artifact.
- Use `npm run deployment:doctor` before provider changes and `npm run deployment:validate` before promotion.
- Keep GitHub repository/commit, Render workspace/service, branch, domain, migration, disk, last-known-good, and rollback identities exact and nonsecret.
- Do not claim deployment, D4/D5, live operation, monitoring, screenshots, or rollback eligibility without exact evidence.
- Do not edit a legal micro-portal repository from this central repository.
- Every new version must include an evidence-based visual, responsive, usability, accessibility, and customer-funnel review of the actual representative public and professional routes on desktop and phone before production acceptance. Review navigation, hierarchy, typography, spacing, information density, forms, calls to action, trust/safety language, funnel continuity, and dead ends. Make changes only when the evidence supports a clearer, more trustworthy, more accessible, more consistent, or more effective experience; never change the interface merely to make a release look different. A reasoned no-change decision is valid and must be recorded. Source tests alone are not visual acceptance, and production acceptance still requires post-deploy route and screenshot verification with rollback on material regression.
