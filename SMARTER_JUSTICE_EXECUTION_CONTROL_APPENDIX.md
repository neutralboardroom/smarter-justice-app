# Smarter Justice Execution Control Appendix

This appendix strengthens execution without superseding compatible product requirements.

## 1. Current-state control sheet

Every continuation prompt must begin with one authoritative block containing the current exact artifact, checksum, size, entry count, Node version, test count, deployment truth, production truth, closed gates, immediate priority, and next permitted phase.

## 2. Phase boundaries

Keep these phases separate and record evidence before advancing:

1. prompt and artifact intake;
2. untouched baseline verification;
3. discrepancy review;
4. justified implementation;
5. source-level tests;
6. final artifact creation;
7. clean-extraction exact-artifact test;
8. deployment preparation;
9. controlled deployment;
10. live acceptance;
11. paid-pilot evidence;
12. owner activation.

Do not mix deployment or activation with source modification.

## 3. Requirement traceability

For every material requirement, maintain:

- stable ID;
- governing source;
- implementation location;
- tests;
- external evidence required;
- current status;
- owner decision;
- rollback method.

## 4. Evidence classes

Label evidence as one of:

- prompt assertion;
- source-code evidence;
- automated-test evidence;
- exact-artifact evidence;
- local-runtime evidence;
- production-configuration evidence;
- live-production evidence;
- real-device evidence;
- external-provider evidence;
- legal/operational approval;
- owner approval.

One class must not be represented as another.

## 5. Discrepancy register

Record conflicts among prompts, code, manifests, tests, release notes, configuration, production, and owner instructions. Do not silently choose one. Apply source priority, explain the resolution, and preserve the unresolved item if evidence is incomplete.

## 6. No-change ledger

For every significant area inspected and preserved, record why no change was justified. A new version is not itself evidence that a change is beneficial.

## 7. Supply-chain requirements

Every release must include:

- lockfile-based clean installation;
- approved-registry portability check;
- dependency vulnerability result;
- SPDX or CycloneDX SBOM;
- secret scan;
- package checksum;
- final-ZIP path and symlink safety;
- Node/runtime requirement.

## 8. Recovery requirements

Before paid or sensitive activation, the owner must approve explicit recovery-point and recovery-time objectives. Backup creation alone is insufficient; restore into a separate environment, integrity checks, timing, responsible person, and rollback evidence are required.

## 9. Browser, device, and accessibility acceptance

Before broad launch or payments, test the current and previous major versions of Chrome, Edge, Safari, and Firefox where available; current iOS Safari and Android Chrome; narrow phone, standard phone, tablet, laptop, and zoom/large-text modes. Target WCAG 2.2 AA unless a documented specialty requirement justifies a stronger standard or a temporary exception with remediation.

## 10. AI safety and change control

Before enabling a new AI provider, model, prompt, tool, or agentic action, test:

- prompt injection and instruction conflict;
- invented facts and false certainty;
- provenance preservation;
- deadline and numerical extraction;
- refusal and escalation behavior;
- sensitive-data handling;
- cross-portal leakage;
- model-change regression;
- human-review triggers;
- consent boundaries.

Record provider, model, prompt/version, test set, results, known limitations, and rollback.

## 11. Performance and availability

Define and approve target-environment acceptance for response latency, concurrency, error rate, database connection recovery, queue/backlog behavior, and provider timeout/fallback. Do not infer production capacity from local tests.

## 12. Named responsibility

Before paid activation, identify the person responsible and backup for owner security, deployment, database recovery, email delivery, Stripe reconciliation, customer support, refunds, complaints, privacy incidents, security incidents, legal escalation, and emergency shutdown.
